# 빨간펜 리뷰 루프

사람은 브라우저에서 HTML 위에 고칠 곳을 직접 표시하고, 너는 **이 대화의 맥락을 유지한 채** 그 표시를 받아 HTML(또는 내용이 들어 있는 JS 파일)을 고친다. 수정 요청에는 슬라이드 번호·원문·앞뒤 문맥·DOM 경로·소스 `파일:행`이 들어 있어서 페이지를 추측할 필요가 없다.

## 1. 시작

1. 대상 HTML을 정한다 — 사용자가 말한 파일, 없으면 이 대화에서 만들거나 고친 HTML. 후보가 여러 개라 애매하면 물어본다.
2. `redpen open <html> --lang <ko|en>` 을 실행하고 출력된 주소를 사용자에게 알려 준다 (브라우저가 자동으로 열린다). `--lang`은 사용자가 이 대화에서 쓰는 언어로 — 한국어면 `ko`, 영어면 `en`. 화면과 수정 요청이 그 언어로 나온다.
3. 사용자의 언어로 한 줄 안내한다:
   - 한국어: "텍스트를 드래그해 D(삭제)·R(수정)·C(코멘트), 배치는 '레이아웃'에서 끌어서 옮기고 모서리로 크기, 빈 곳은 '영역'으로 표시하고 [AI에게 보내기]를 누르세요."
   - English: "Drag over text and press D (delete), R (replace) or C (comment); in 'Layout' drag things to move them and use the corners to resize; mark empty space with 'Area', then press [Send to AI]."
4. 곧바로 2단계로 대기에 들어간다.

## 2. 수정 요청 기다리기

- **Claude Code**: `redpen wait <html>` 을 Bash 도구의 `run_in_background: true` 로 실행한다. 사용자가 [AI에게 보내기]를 누르면 명령이 끝나고 완료 알림이 오며, 그 출력(stdout)이 곧 수정 요청이다. 기다리는 동안 턴을 마쳐도 된다.
- **Codex (Orca 포함)**: `exec_command`로 `redpen wait <html>` 을 실행한다 (`yield_time_ms: 1000`). 실행 중인 `session_id`가 반환되면 `write_stdin`으로 같은 세션의 출력을 계속 받는다 (`chars: ""`, `yield_time_ms: 10000`). 요청이 오기 전까지 턴을 끝내지 않는다. 출력된 수정 요청을 받으면 바로 3단계로 간다. 시간 제한을 따로 설정했다면 종료 코드 2일 때 대기를 다시 시작한다.
- `yield_time_ms`는 도구가 출력을 돌려주는 간격이지 리뷰 제한 시간이 아니다. 출력이 비어 있어도 `session_id`가 있고 `exit_code`가 없으면 대기 중이므로 같은 세션을 계속 확인한다. 사용자가 대기 시간을 정하지 않았다면 `--timeout`을 붙이지 않는다. 몇 차례 확인했거나 일정 시간이 지났다는 이유로 대기를 마치지 않는다.
- Codex의 명령 세션은 Claude Code의 백그라운드 완료 알림처럼 끝난 대화를 자동으로 재개하지 않는다. "보내면 알려 주세요"라고 턴을 끝내거나 `&`·`nohup`·출력 파일만 남기는 방식으로 대체하면 자동 수신이 끊긴다. `redpen status <html> --json`의 `agent`로 대기 프로세스가 실행 중인지 확인할 수 있다.
- 지속 실행 도구가 없거나 사용자가 수동 반영을 원할 때만 아래 수동 모드를 쓴다. 자동 수신을 유지할 수 없다면 그 사실을 먼저 알린다.

## 3. 반영

- 출력의 `#번호` 항목을 **하나도 빠짐없이** 반영한다. 출력 맨 위의 "반영 규칙"을 따른다.
- 🗑 **삭제**: 그 텍스트·요소·슬라이드만 지우고, 비게 된 태그와 남는 구두점·공백도 정리한다.
- ✏️ **수정**: `원문` → `변경` 그대로 바꾼다. 굵게·링크 같은 주변 서식은 유지한다.
- 💬 **코멘트**: `지시`를 해석해 반영한다. 대상이 영역이면 위치(예: "오른쪽 위")와 "영역 안 요소"를 참고한다.
- 📐 **레이아웃**: 사람이 화면에서 직접 옮기고·키우고·순서를 바꿔 본 결과다. 그 모습이 되도록 HTML/CSS를 고치되 `translate`나 절대 좌표로 흉내 내지 말고, "지금:"에 적힌 원래 방식(flex·grid·몇 번째 칸)에 맞게 순서·크기·간격·글자 크기를 바꾼다. %·px는 목표값 참고용이다.
- 📐 **새 배치 스케치**: 칸의 위치·비율과 이름대로 슬라이드를 다시 구성한다("지금 그 자리" = 지금 그 칸에 있는 요소). **슬라이드 순서 옮기기**는 슬라이드를 통째로 그 번째로 옮긴다.
- 내용이 HTML이 아니라 JS(예: `slides.js`)에 있으면 그 파일을 고친다 — `소스: 파일:행`을 참고한다 (편집 전 기준이므로 여러 곳을 고칠 땐 문자열로 찾는다).
- 같은 문구가 여러 곳이면 슬라이드 번호·문맥(⟦ ⟧ 안이 표시한 부분)·소스 후보로 정확한 위치를 고른다.
- 요청하지 않은 곳은 건드리지 않는다. 지시가 모호하면 가장 합리적으로 해석하고 그 해석을 답장에 적는다.
- 파일을 저장하면 브라우저가 자동으로 새로고침된다.

## 4. 결과 알리고 다음 라운드

- 반영이 끝나면 `redpen wait <html> --reply "<무엇을 바꿨는지 1~3문장 · 못 한 항목은 이유>"` 를 2단계와 같은 방식으로 실행한다. Claude Code는 백그라운드 실행, Codex는 명령 세션의 출력을 계속 받는다. 답장이 브라우저에 뜨고 다음 수정 요청을 기다린다.
- 사용자에게도 같은 내용을 짧게 알리고 대기를 이어간다 (Codex는 commentary). `redpen done`만 실행하고 턴을 끝내면 다음 요청을 자동으로 받지 못한다. 답장(`--reply`)과 안내는 사용자가 쓰는 언어로 쓴다.
- 사용자가 리뷰를 끝내자고 하면 `redpen done <html> --reply "<요약>" --stop` 을 실행한다 (기다리던 wait도 끝나고 리뷰 화면도 꺼진다).
- `redpen wait` 이 "사용자가 브라우저에서 빨간펜을 종료했습니다"로 끝나면 사용자가 툴바의 ⏻ 종료로 리뷰를 끝낸 것이다. 다시 기다리지 말고 짧게 마무리한다 (다시 하려면 `redpen open` 부터).

## 대기가 끊긴 뒤 다시 연결

기다리는 세션 없이 사용자가 먼저 보냈다면("리뷰 반영해줘"): `redpen pending <html>` → 반영 → 4단계의 `redpen wait <html> --reply "..."` 로 자동 대기를 다시 연결한다. 가져올 요청이 없어도 2단계로 대기한다. 사용자가 명시적으로 수동 반영만 원할 때는 `redpen done <html> --reply "..."` 로 결과만 알린다.

## 참고

- `<html>` 을 생략하면 마지막으로 연 파일을 쓴다. 폴더를 주면 그 안의 `index.html` 을 연다.
- 슬라이드 번호가 이상하면(감지 실패) `redpen open <html> --slide "<슬라이드 요소 선택자>"`.
- `redpen status <html>` 상태 확인 · `redpen stop <html>` 서버 종료.
- 사용자가 빨간펜을 어떻게 끄는지 물으면: 툴바 맨 오른쪽 ⏻(종료)를 누르거나, 이 세션에 "리뷰 끝"이라고 하면 된다.
- 사용자가 화면 언어를 바꾸고 싶어하면 `redpen open <html> --lang en`(또는 `ko`) — 열린 탭도 그 언어로 바뀐다.
- `redpen` 명령이 없으면 사용자에게 설치를 안내한다: `npm install -g @woosopyi/redpen && redpen setup`.
- 리뷰 데이터는 `<HTML 폴더>/.redpen/` 에 저장되며 git에서 자동 제외된다.
